## Building and running

A POSIX environment and a C compiler are required. After downloading the
dependencies, build and run the test program with:

```sh
cc -std=gnu11 -O2 -Wall -Wextra -o ai-test-iip main.c
./ai-test-iip
```

A successful test run exits with status `0`. The tests use `assert`, so do not
build with `NDEBUG` defined.

### TCP Fast Open capability test

The iip test includes `TFO-PASSIVE-1`. It requests a TCP Fast Open cookie (option kind 34), then uses the
returned cookie with SYN data. A supported implementation must accept and
deliver that data once before the final handshake ACK, suppress duplicate
delivery on SYN retransmission, and complete the handshake without repeating
the early callbacks.

The normal suite reports an unsupported implementation as TAP `TODO`. Run the
capability test alone to require support and receive a nonzero exit status when
it is unavailable:

```sh
./ai-test-iip --fast-open
```

### Make targets

Build and run the full test suite with:

```sh
make
make check
```

Run the suite with AddressSanitizer and UndefinedBehaviorSanitizer:

```sh
make check-asan
make check-ubsan
make check-sanitizers
```

The sanitizer builds use separate binaries, stop at the first reported error,
and retain frame pointers for useful stack traces. The ASan target disables
leak detection so it also works in test runners that execute processes under
`ptrace`; it still checks invalid memory accesses.

The enhanced negative and state-transition tests are expected to expose known
failures in the current stack. A nonzero exit status can therefore represent a
successfully detected implementation defect rather than a test harness crash.

### Reproducible packet fuzzing

The packet mutator uses a deterministic seed. The seed, case count, and failure
artifact prefix can be selected with environment variables:

```sh
IIP_FUZZ_SEED=0x12345678 \
IIP_FUZZ_CASES=1000 \
IIP_FUZZ_FAILURE_PREFIX=./iip-fuzz-failure \
./ai-test-iip
```

When a fuzz case crashes, asserts, or times out, the mutated packet is saved as
a `.bin` file and its seed, case number, length, and path are saved in a matching
`.txt` file.
