# ai-test-iip

This repository contains a test program for the
[iip](https://github.com/yasukata/iip) TCP/IP stack. It includes RFC 9293
tests, legacy regression tests, and self-tests for packet construction and
event logging.

## AI-generated implementation

The original implementation in `main.c` and the original README were generated
entirely by OpenAI Codex. The expanded malformed-input, boundary-value, TCP
state-transition, reproducible fuzzing, positive-control, and RFC section
mapping implementation was generated by M365 Copilot based on the GPT-5
reasoning model.

This repository contains no manually implemented code. Review, testing, and
validation are still required before using the test suite as a conformance or
security assurance artifact.

## Repository contents

The following project files are published in this repository:

- `main.c` — harness entry point, packet builders, legacy scenarios, and self-tests
- `test_fixture.h` — shared connection fixtures and assertions
- `test_process.h` — isolated execution, result transport, and timeout handling
- `test_tcp.h` — includes the `test_tcp_*.h` scenario modules in dependency order
- `test_tcp_model.h` — independent RFC input model for synchronized states
- `test_tcp_traces.h` — handshake states and actual open/close traces with control loss
- `test_tcp_sequence.h` — six sequence boundaries, ACKs, retransmission, windows and SACK
- `test_ipv4.h` — IPv4 host and ICMP scenarios
- `test_tcp_extensions.h` — Window Scale, Timestamps, and reset scenarios
- `test_api.c` and `test_api.h` — adapters and helpers for the current iip API
- `test_backend.c` and `test_backend.h` — packet backend and callback bindings
- `test_wire.h` — test-side wire-format definitions
- `test_report.h` — TAP and JSON serialization with single-line TAP text
- `Makefile` — build and test targets
- `README.md` — setup, build, and usage instructions
- `LICENSE` — the MIT License

The scenario headers are included by `main.c` in dependency order and share its
static helpers. The harness remains a single translation unit, so the direct
compiler command below continues to work.

TCP scenarios are grouped into send/retransmission, malformed input, connection
states, Fast Open, socket operations, keep-alive, urgent data, network-layer
interaction, window control, wire-format fields, and option validation modules. Shared operations such as
`fixture_advance_ms` and `fixture_input_packet` prepare inputs without hiding
scenario-specific expectations. IPv4 input variations are listed in
`ip4_input_cases`, with separate registry functions for independent execution.

Use `TEST_REQUIRE(why, condition, format, ...)` in result-returning scenarios to
report expected and actual values in diagnostics and TAP/JSON. Boolean helpers
can use `TEST_CONDITION` or `TEST_ACCUMULATE`; their detail is used when a failed
scenario does not supply its own reason. `make check-harness` also builds a
separate synthetic registry to check reporting statuses and exit codes without
depending on failures in the target implementation. The runner self-checks also
exercise option validation against malformed lengths and padding using exact-size
buffers, so sanitizer runs can detect reads beyond the declared option area.
TAP descriptions and reasons escape control characters, backslashes, and `#` so
free text cannot create extra result lines or SKIP/TODO directives. A `[` after
` - ` is also escaped so descriptions and reasons cannot imitate status markers.
JSON retains the original text, and console-wrapper tests check that statuses
remain intact.

Run `make check-harness-sanitizers` to exercise these checks with ASan and UBSan
independently of target-stack conformance failures.

The iip and BLAKE2 sources are intentionally not included. Download
them separately from their upstream locations as described below.

## Downloading dependencies

Run these commands in the repository root (the directory containing this
README):

```sh
git clone https://github.com/yasukata/iip.git iip
git clone https://github.com/BLAKE2/BLAKE2.git blake2-upstream
cp blake2-upstream/ref/blake2.h .
cp blake2-upstream/ref/blake2-impl.h .
```

## Building and running

A POSIX environment and a C compiler are required. After downloading the
dependencies, build and run the test program with:

```sh
cc -std=gnu11 -O2 -Wall -Wextra -o ai-test-iip main.c
./ai-test-iip
```

Run the harness self-tests, including a two-endpoint TCP handshake, bidirectional
payload transfer, and connection teardown, with:

```sh
./ai-test-iip --self-tests
```

Self-tests use the same isolated execution and result transport as protocol
cases. Their timeout remains 10 seconds per test (30 seconds for protocol cases).
A parent-side watchdog enforces the deadline with a one-second grace period even
if a test ignores its alarm. Event-log overflow and missing child reports fail
the self-test, and diagnostics include the failing self-test name and reason.

A successful test run exits with status `0`. The tests use `assert`, so do not
build with `NDEBUG` defined.

### Case selection and reporting

```sh
make check-harness
./ai-test-iip --list
./ai-test-iip --case MUST-13 --case MUST-40 --json results.json
./ai-test-iip --no-tfo
./ai-test-iip --strict-api --blake2
make check
make check-asan
make check-ubsan
make check-mutations
make check-conformance
```

TFO is enabled by default. Use `--no-tfo` when it is outside the selected
configuration. `--fast-open` selects only TFO cases. Failures are not
unconditionally converted to TODO results.

`requirements.json` records case requirements, references, profiles, observation
criteria, and coverage gaps. Run `make registry` after editing it, then
`make check-registry` to check synchronization with the generated C registry.
`test_runner.h` provides TAP and JSON reporting; `conformance_tests.h` contains
additional scenarios.

`make check` saves formatted diagnostics to `test-results.log`.
The wrapper drains stdout and stderr separately, parsing TAP only from stdout
while retaining both streams in the diagnostic log.
The command runs in its own POSIX process group. When it exits or output logging
fails, the wrapper stops remaining processes in that group so inherited output
pipes cannot keep the wrapper waiting indefinitely.
SIGINT (Ctrl+C) and SIGTERM also stop the command's process group, with a brief
interruption diagnostic and exit codes 130 and 143 respectively.
Its `run_tests.py` wrapper requires the harness's nonempty TAP stream, with a
version header, a plan before the cases, and consecutive case numbers. Missing,
truncated, or malformed results turn a zero child exit into exit code 2; existing
nonzero child exit codes are preserved. Contradictory result fields, unsupported
status markers, and SKIP/TODO directives without a reason are reported as errors.
TAP counts and case numbers must use ASCII digits; numbers that exceed Python's
integer conversion limit are reported as invalid TAP rather than raising a traceback.
Run `--list` and `--self-tests` directly rather than through this case-results
wrapper.

A failed stdout write during case reporting or `--list` returns exit code 2.
When JSON is requested, a TAP write failure is reflected in its `exit_code`
without changing the individual case observations.
`make check-conformance` saves source snapshots, hashes, revisions, diffs,
configuration, TAP, JSON, and diagnostics under `artifacts/conformance/`.
To use a different output directory:

```sh
python3 scripts/capture_run.py --output artifacts/my-run -- ./ai-test-iip --no-tfo
```

Reusing an output directory overwrites its files. Generated artifacts are not
tracked by Git. Preserve the complete evidence directory and corresponding
sources when sharing a run.

Sanitizers run in each child process. ASan leak detection is disabled.
Abnormal termination is recorded as a failure or execution error, and subsequent
cases continue running.

### Evaluation scope

The evaluated system combines iip over IPv4 with this repository's callbacks,
packet backend, and API adapters. It does not cover IPv6 or certify iip in
isolation. References include RFCs 9293, 1122, 791, 768, 2018, 6298, 5681, 7323,
and 7413; per-case references appear in `requirements.json`.

The `base`, `tfo`, `regression`, `strict-api`, and `blake2` profiles run by
default. Implementation-specific contracts and the BLAKE2 known answer check
therefore run without extra options. `--strict-api` and `--blake2` remain
accepted for compatibility. The runner sets `IIP_TEST_STRICT_API_CONTRACT=1`
and `IIP_TEST_BLAKE2_PROFILE=1`, overriding inherited values so in-test guards
agree with profile selection. The BLAKE2 check is not a proof of cryptographic
security. `--no-tfo` continues to disable TFO cases.

Packet construction, checksum verification, virtual time, and event recording
belong to the harness. Listener behavior, source-address selection, and
application notifications include integration callbacks. Source-route settings
that are not connected to the native API are reported as inconclusive.
Direct ESTABLISHED fixtures do not replace handshake negotiation tests.

`IP4-OPT-2` enables a test-side input adapter that checks IPv4 option lengths,
discards malformed options, and uses iip's IPv4 sender to emit ICMP Parameter
Problem with a pointer to the offending byte. It checks bad-checksum and
non-initial-fragment suppression as well as valid-option delivery. This is
an integration scenario, not a check of iip's native Parameter Problem
generator. The adapter is disabled for other cases. It covers structural
option errors, not option-specific semantics, subnet-directed broadcasts,
rate limiting, or the full set of ICMP error suppression rules.

`UDP-PORT-1` enables a test-side UDP port binding in `test_backend.c`.
The callback delivers bound-port traffic and sends ICMP Port Unreachable for
unbound unicast traffic using iip's IPv4 sender. The case checks bound-port
delivery, silent rejection of an invalid UDP checksum, and the unbound-port
reply including its addresses, checksums, and quoted datagram. This measures
iip plus the test-side UDP integration, not native UDP socket support in iip.
Other UDP cases retain the default callback that delivers all ports. The
integration has one wildcard-address binding and does not model subnet masks,
directed broadcasts, or a complete UDP socket API.

| Status | Meaning |
| --- | --- |
| PASS | The selected scenario satisfied its assertions |
| FAIL | A mandatory or selected profile assertion failed |
| DEVIATION | A SHOULD recommendation was not satisfied |
| NOT_APPLICABLE | A case is inapplicable or its optional profile is disabled, with a reason |
| INCONCLUSIVE | Required capabilities, API bindings, or observations are unavailable |
| ERROR | Execution, recording, or reporting failed |

All cases currently provide partial coverage. **A successful run does not
establish RFC conformance.** JSON reports `conformance: NOT_ESTABLISHED`.
Exit codes are 0 for no failures, inconclusive cases, or execution errors;
1 for failures or inconclusive cases; 2 for execution errors; and 3 when
`--conformance` is requested and cases pass but conformance remains unestablished.

Full state and sequence/time wraparound coverage, timestamp-based RTT
estimation, all congestion-control algorithms, native source-route bindings,
cryptographic evaluation, and a complete RFC update/errata audit remain outside
the established coverage. Multiple cases may cover the same requirement or
expose the same defect; case counts are not requirement coverage percentages.

State-input models and actual handshake and teardown traces complement
sequence cases at `00000000`, `00000001`, `7fffffff`, `80000000`, `fffffffe`,
and `ffffffff`. The ledger records each case's applicability, oracle, and
coverage limits. Its `phase` field groups state cases as 2 and sequence cases
as 3; it does not change default profile selection.

For example:

```sh
./ai-test-iip --case TCP-TRACE-ACTIVE-LOSS --case TCP-TRACE-SIMULTANEOUS-CLOSE
./ai-test-iip --case TCP-SEQ-FFFFFFFF-ACKS --case TCP-SEQ-FFFFFFFF-RETRANSMIT
ASAN_OPTIONS=detect_leaks=0:halt_on_error=1 ./ai-test-iip-asan --case TCP-SEQ-FFFFFFFF-WINDOW
```

Mutation experiments distinguish target defects, permitted target behavior,
and synthetic observer counterexamples. Synthetic ACK scheduling checks the
observer boundary; it is not a modified TCP implementation.

### Reproducible packet fuzzing

The packet mutator uses a deterministic seed. The seed, case count, and failure
artifact prefix can be selected with environment variables:

```sh
IIP_FUZZ_SEED=0x12345678 \
IIP_FUZZ_CASES=1000 \
IIP_FUZZ_FAILURE_PREFIX=./iip-fuzz-failure \
./ai-test-iip
```

When a fuzz case crashes, asserts, or times out, the mutated packet is saved as
a `.bin` file and its seed, case number, length, and path are saved in a matching
`.txt` file.

Python integration tests share `tests/process_support.py`: commands have a
40-second default timeout (console scenarios use shorter explicit limits), run

This also bounds compiler invocations and reporting tests. Wrapper cancellation
can clean up the separate session it owns before the helper escalates to KILL.

Fixture workspace/connection allocation failures are reported as ERROR even
when a boolean scenario helper returns failure. The reason survives TAP/JSON
reporting and is reset for each isolated case. Keep-alive, sequence wrap, initial
RTT, and simultaneous-close diagnostics include expected and observed values.

Additional regression profiles exercise receive reordering, duplicate delivery
and FIN across sequence wrap; keep-alive across the 32-bit millisecond clock
wrap; and an 800 ms initial RTT sample. Sequence and clock tests include matching
non-wrapping controls. Keep-alive is observed at 999 ms and 1499 ms to account for
the 500 ms timer evaluation interval. These use white-box fixture placement and
remain partial coverage: the newer `TCP-MODEL-*`, `TCP-TRACE-*`, and `TCP-SEQ-*`
cases separately extend state and sender ACK coverage. Other timers, timestamp
negotiation, initial RTO and RTT rounding are not established by these original
regression profiles.

Harness fault checks build in a fresh temporary directory and remove it on exit,
so independent invocations do not overwrite each other's executables. Isolated
C cases own a process group; remaining descendants are stopped after a report,
a timeout, or parent cancellation. SIGINT/SIGTERM are blocked while that group
is being registered, and restored before the next case.

The console wrapper defers cancellation during command and reader-thread startup
until cleanup owns the new resource. Further cancellation signals are ignored
while the first interruption unwinds. Output buffering is bounded to 256 queued
lines, each at most 65536 characters. Longer lines produce an output error;
consumer failure releases readers even when the queue is full.

Mutation experiments bound builds to 60 seconds and runs to 40 seconds. Build
errors, timeouts, missing or inconsistent JSON and mutation failures are recorded
as ERROR, with the experiment stage and diagnostic. Later experiments continue,
and summary.json is replaced after each experiment. Old per-run JSON is removed
before execution so missing output cannot reuse a previous result.
The wrapper allows the command up to one second after TERM to clean up its own
isolated groups before sending KILL to remaining members of the command group.
